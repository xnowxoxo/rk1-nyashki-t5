# РК1 · Трек 5 · Множество Мандельброта

Хакатон PARAM BILIM Speedup Challenge, РК1, раунд 2.
Картинка 4096 × 4096, до 2000 итераций на точку, область [−2; 1] × [−1,5; 1,5].

Команда:
- Шамиль Н. - MPI (`src/mpi.c`)
- Аюпов И. - OpenMP (`src/omp.c`)

## Структура

```
src/      mandel.h  seq.c  mpi.c        MPI-часть и её эталон
          seq_omp.c  omp.c              OpenMP-часть и её эталон
slurm/    omp.sbatch  mpi.sbatch
scripts/  analyze.py                    графики MPI
          plot_omp.py                   графики и таблица OpenMP
logs/     *.out из Slurm, без правок (omp_2485.out — OpenMP)
plots/    speedup.png  efficiency.png                            MPI
          omp_speedup.png  omp_efficiency.png  omp_metrics.md    OpenMP
```

`mandel.h` общий для seq и mpi: параметры и функция расчёта одной точки. Поэтому результат у них совпадает побитово.
`seq_omp.c` и `omp.c` используют одну и ту же функцию расчёта строки, поэтому их картинки тоже совпадают побитово.

## Проверка корректности

seq и mpi считают контрольную сумму картинки с весом позиции, Σ img[i]·(i+1). Так ловятся и неверные значения, и строки, собранные не на своё место.
`seq` при первом запуске записывает эталон в `ref_4096.txt`. `mpi` сверяется с ним и печатает `CHECK: OK`/`FAIL`.

`seq_omp` проверяет, что картинка зеркально симметрична (строки y и N−1−y побитово равны), и печатает хеш FNV-1a всех пикселей по порядку.
`omp` получает этот хеш аргументом и сверяется с ним. Неверное значение пикселя или строка не на своём месте меняют хеш.

Формат вывода: `version;p;time_s;CHECK`. Строки с `#` служебные. `#detail` у MPI показывает время счёта самого быстрого и самого медленного процесса и время сбора.
У OpenMP строка `# hash=… imbalance=…`: хеш картинки и дисбаланс = работа (сумма итераций) самого загруженного потока / средняя.

## Декомпозиция в MPI

Строки раздаются циклически: процесс r считает строки r, r+p, r+2p, … Тяжёлые строки идут через середину картинки подряд, и при раздаче блоками почти вся работа досталась бы средним процессам. При циклической раздаче у каждого процесса есть и лёгкие, и тяжёлые строки.

Каждый процесс получает N/p строк, первые N mod p процессов — на одну больше. Rank 0 собирает куски через `MPI_Gatherv` (counts и displs по этим размерам) и расставляет строки по местам.

Для сравнения есть блочная раздача: `MANDEL_DIST=block`.

## Расписания в OpenMP

Цикл по строкам y распараллелен через `#pragma omp for schedule(runtime)`, расписание задаётся переменной `OMP_SCHEDULE`. Так все варианты сравниваются на одном бинарнике:

| `OMP_SCHEDULE` | как раздаются строки |
|---|---|
| `static` | сплошными блоками по N/p строк, как `MANDEL_DIST=block` в MPI |
| `static,1` | по кругу: поток t считает строки t, t+p, t+2p, …, как циклическая раздача в MPI |
| `dynamic,1` | свободный поток берёт следующую строку из общей очереди |
| `guided` | порции начинаются примерно с N/p строк и уменьшаются до 1 |

Для дисбаланса каждый поток копит сумму своих итераций в локальной переменной и записывает её в массив один раз после цикла, поэтому гонок нет.

Замеряется только вычислительный цикл: выделение памяти и проверка в замер не входят.
Серия: 1, 2, 4, 8, 16, 32 потока, по 3 запуска на каждое расписание; каждый поток на своём физическом ядре
(`OMP_PLACES=cores`, `OMP_PROC_BIND=close`).

## Как воспроизвести на PARAM BILIM

```bash
# на bilim-master (на вычислительных узлах нет заголовков C)
module load intel/mpi/2021.14
make                         # bin/seq, bin/omp, bin/mpi + копия libgomp для узлов

mkdir -p logs
sbatch slurm/mpi.sbatch      # seq ×3 + MPI 1..64 процесса ×3, 2 узла
sbatch slurm/omp.sbatch      # сам собирает bin/seq_omp и bin/omp на pbcn02; seq_omp ×3 + OpenMP 1..32 потока ×3, static / static,1 / dynamic,1 / guided, ~11 минут
squeue -u $USER

# когда оба задания закончатся
python3 scripts/analyze.py       # results.md + plots/ для MPI
python3.11 scripts/plot_omp.py   # plots/omp_* для OpenMP, нужен matplotlib (есть в python3.11 на bilim-master)
```

Для быстрой проверки на маленькой картинке: `MANDEL_N=512 ./bin/seq`, потом `MANDEL_N=512 ...` для MPI (у OpenMP-части размер задан в исходниках).

Ручной запуск OpenMP: `./bin/seq_omp` печатает `# hash=<H>`, затем `OMP_SCHEDULE=dynamic,1 OMP_NUM_THREADS=8 ./bin/omp <H>`.

## Окружение

OpenMP-замеры: pbcn02, 2 × Intel Xeon Gold 6336Y @ 2.40 GHz, 2 сокета × 24 ядра, HT = 2, 2 NUMA-узла; gcc 8.5.0; `--exclusive`.
Соседние по номеру ядра на этом узле лежат на разных сокетах, поэтому при `close` потоки чередуются между сокетами:
уже при p = 2 работают оба сокета, при p = 32 — по 16 потоков на каждом.

MPI: заполнить `mpicc -v` / `mpirun --version`.
